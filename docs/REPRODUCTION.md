# Reproduction record

`make reproduce` re-runs the pipeline into `build/reproduce/`, touching
nothing committed, then compares every regenerated number with `results/`
(`physprior verify`, relative tolerance 1e-9, wall-clock `seconds` and
`environment.json` ignored) and checks the generated tables
(`physprior report --check`).

## 2026-09-26

| | |
|---|---|
| code | commit `d312e06`, clean tree |
| environment | Python 3.13.1, macOS 13.4 arm64, CPU float64, `tools/requirements.lock` sha256 `71cc42f3…` |
| commands | `physprior run all`, then `physprior neglected`, offline, from the cached `data/raw/` |
| verdict | **0 files differ.** 22 identical byte for byte; 23 with every number equal and only timings changed; 125 not regenerated |
| report check | the README and `docs/RESULTS.md` tables match `results/` |

The 125 files not regenerated are outputs of other commands: the tuning
studies (`physprior tune`, `results/*/tune/`), the report (`headline.json`),
`quantum/helium` (added after this run started), and the studies across
problems (`reconstruct`, `dynamics`, `optim`, `theory`, `run fields`), which
record their own settings and are regenerated by their own commands.

Wall time was 5.7 hours, of which `run all` took 41 minutes and the
neglected-terms study the rest. Neither figure is a benchmark: for most of
the neglected study the machine was running several other studies at once.

The symbolic-regression searches were served from the local cache
(`.cache/sr/`, keyed on data and configuration), so this run checks that the
cached searches reproduce the committed tables, not that a fresh search on a
new machine does. PySR runs `deterministic=True` with a fixed seed, which is
what a fresh search relies on.
